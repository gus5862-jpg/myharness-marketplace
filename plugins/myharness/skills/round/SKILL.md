# 라운드 진행

한 라운드는 문서 세 개(`spec.md` → `plan.md` → `review.md`)와 함께 끝까지 간다.

## 문서 위치
- `docs/ROADMAP.md`: 라운드 계획. 지금 어느 라운드인지 여기서 확인한다.
- `docs/SSOT.md`: 진실의 원천. 지금 서비스의 API, 데이터 모델, 규칙.
- `docs/roundNN/`: 라운드마다 `spec.md` · `plan.md` · `review.md`. (NN은 두 자리, 예: round04)

프로젝트에 이 파일이 없으면 만들기 전에 사람에게 위치를 확인한다.

## 순서
1. **확인**: ROADMAP에서 이번 라운드 번호와 목표를 읽고, SSOT로 지금 상태를 파악한다.
2. **spec**: `docs/roundNN/spec.md`에 무엇을 만드는지, 입력 · 출력, 경계값, 실패 경우를 적는다. 사람에게 확인받는다.
3. **plan**: `plan.md`에 바꿀 파일과 순서, 테스트 계획을 적는다.
4. **구현**: CLAUDE.md의 코드 규칙을 지킨다. 린트 Hook에 걸리면 지침대로 고친다.
5. **검증**: `verifier` 에이전트로 spec 대비 검증을 받는다. 문제를 고치고 다시 검증한다.
6. **정리**: `cleaner` 에이전트로 죽은 코드 · 어긋난 문서를 정리한다.
7. **review**: `review.md`에 한 일, 검증 결과, 정리 결과, 남은 일을 적는다.

## 종료 조건
아래를 모두 지켜야 라운드가 끝났다고 보고한다. 하나라도 안 되면 무엇이 남았는지 보고한다.
1. `docs/roundNN/spec.md` · `plan.md` · `review.md`가 지금 코드와 맞는다.
2. `docs/SSOT.md`를 지금 코드 기준으로 고쳤다. (현재 라운드, API 목록, 데이터 모델)
3. cleaner 에이전트로 죽은 코드를 정리했고, 결과를 `review.md`에 적었다.
4. CLAUDE.md에 적힌 테스트 · 린트 명령이 통과한다.
5. `docs/ROADMAP.md`에서 이번 라운드를 완료로 표시했다.
